Lists, checks, grants and revokes the access users and groups have to an
organization, with the roles it gives them. The organization is the one the
API key belongs to unless --org names another. Users are given by id or
email, groups by id or name, roles by id or display name.

```sh
bronto access <command> [flags]
```

#### Subcommands

| Command | Description |
| --- | --- |
| [`bronto access check`](/cli/reference/commands/access#bronto-access-check) | Show whether a user or group has access, and its roles |
| [`bronto access grant`](/cli/reference/commands/access#bronto-access-grant) | Give a user or group access to the organization |
| [`bronto access list`](/cli/reference/commands/access#bronto-access-list) | List the users and groups with access to the organization |
| [`bronto access revoke`](/cli/reference/commands/access#bronto-access-revoke) | Remove a user's or group's access to the organization |

Also accepts the [global flags](/cli/reference/commands/global-flags).

## bronto access check

Takes exactly one of --user and --group.

```sh
bronto access check [flags]
```

#### Flags

| Flag | Short | Type | Default | Description |
| --- | --- | --- | --- | --- |
| `--group` |  | string |  | the group, by id or name |
| `--org` |  | string |  | organization id (default: the API key's active or only organization) |
| `--user` |  | string |  | the user, by id or email |

Also accepts the [global flags](/cli/reference/commands/global-flags).

#### Examples

```sh
bronto access check --user ada@example.com
bronto access check --group sre -o json --jq .is_authorised
```

## bronto access grant

Grants one user (--user) or one group (--group) access with the given roles; 'bronto roles list' shows their ids and names.

```sh
bronto access grant [flags]
```

#### Flags

| Flag | Short | Type | Default | Description |
| --- | --- | --- | --- | --- |
| `--group` |  | string |  | the group, by id or name |
| `--org` |  | string |  | organization id (default: the API key's active or only organization) |
| `--roles` |  | strings |  | roles to give, by id or display name (comma-separated or repeated) |
| `--status` |  | string | `active` | status of the grant: active or invited |
| `--user` |  | string |  | the user, by id or email |

Also accepts the [global flags](/cli/reference/commands/global-flags).

#### Examples

```sh
bronto access grant --user ada@example.com --roles ReadOnly
bronto access grant --group sre --roles Admin,<role> --dry-run
```

## bronto access revoke

Takes exactly one of --user and --group. Asks for confirmation unless --yes is passed.

```sh
bronto access revoke [flags]
```

#### Flags

| Flag | Short | Type | Default | Description |
| --- | --- | --- | --- | --- |
| `--group` |  | string |  | the group, by id or name |
| `--org` |  | string |  | organization id (default: the API key's active or only organization) |
| `--user` |  | string |  | the user, by id or email |
| `--yes` |  | bool |  | skip the confirmation prompt |

Also accepts the [global flags](/cli/reference/commands/global-flags).

#### Examples

```sh
bronto access revoke --user ada@example.com --yes
```
