EXPERIMENTAL PROTOTYPE: flags, output and behavior will change.

Creates a Bronto account and organization, waits until you click the link in
the verification email, then creates an API key and stores it as a profile,
like 'bronto auth login'.

Anything not given as a flag is asked for when a terminal is attached. With
every flag given it never prompts. The region (--region eu|us) is permanent:
an organization cannot move to another region later.

No access to a browser? 'bronto signup confirm' takes the link (or the code
in it) from the email; a waiting 'bronto signup' then continues by itself.
If the wait ran out, run the same command again with the same password.

```sh
bronto signup [flags]
bronto signup <command> [flags]
```

#### Subcommands

| Command | Description |
| --- | --- |
| [`bronto signup confirm`](/cli/reference/commands/signup#bronto-signup-confirm) | Verify a sign-up email from the terminal (experimental prototype) |

#### Flags

| Flag | Short | Type | Default | Description |
| --- | --- | --- | --- | --- |
| `--accept-terms` |  | bool |  | accept the terms of service (https://www.bronto.io/legal/terms) |
| `--email` |  | string |  | email address to sign up with (it gets a verification link) |
| `--first-name` |  | string |  | your first name |
| `--generate-password` |  | bool |  | generate the account password and print it once |
| `--last-name` |  | string |  | your last name |
| `--org` |  | string |  | name of the organization to create |
| `--password-stdin` |  | bool |  | read the account password from stdin instead of prompting |
| `--wait` |  | duration | `30m0s` | how long to wait for the email verification |

Also accepts the [global flags](/cli/reference/commands/global-flags).

#### Examples

```sh
bronto signup
bronto signup --email ada@example.com --first-name Ada --last-name Lovelace \
  --org 'Analytical Engines' --region eu --accept-terms --generate-password
```

## bronto signup confirm

EXPERIMENTAL PROTOTYPE.

Does what clicking the link in the verification email does. Pass the whole
link (in quotes); the email address and region are read from it. With only
the confirmation code, pass --email and --region too.

A 'bronto signup' that is waiting for this account continues by itself.

```sh
bronto signup confirm <link-or-code> [flags]
```

#### Flags

| Flag | Short | Type | Default | Description |
| --- | --- | --- | --- | --- |
| `--email` |  | string |  | the email address being verified (read from the link when given one) |

Also accepts the [global flags](/cli/reference/commands/global-flags).

#### Examples

```sh
bronto signup confirm 'https://app.eu.bronto.io/verify?confirmation_code=123456&email=ada@example.com'
bronto signup confirm 123456 --email ada@example.com --region eu
```
