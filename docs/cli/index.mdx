`bronto` is a command-line client for the [Bronto](https://bronto.io) observability
platform. It wraps Bronto's REST and ingestion APIs, so anything you do in the web app
you can also do in a shell script, a CI job, or an agent's tool call. It's a single
binary with scriptable output and stable exit codes.

<Note>
**Open source and community-supported.** The bronto CLI is developed in the open at
[bronto-community/bronto-cli](https://github.com/bronto-community/bronto-cli) under the MIT license. It is
supported by its community, not by Bronto's support team: report bugs, ask questions, and
suggest features in [GitHub issues](https://github.com/bronto-community/bronto-cli/issues). Contributions are welcome.
</Note>

## What you can do

<CardGroup cols={2}>
  <Card title="Search logs" icon="search" color="#8E51FF" href="/cli/guides/searching">
    Run one-shot queries with `bronto search`, or let filter flags like `--eq` and `--gt`
    write the WHERE clause for you.
  </Card>
  <Card title="Follow live" icon="rocket" color="#00A6F4" href="/cli/guides/live-tail">
    `bronto tail` streams new events like `tail -f`, or redraws a live group-by every few
    seconds.
  </Card>
  <Card title="Explore traces" icon="workflow" color="#00BBA7" href="/cli/guides/traces">
    See a trace's waterfall, latency per service, and the call-tree shape merged across
    many traces.
  </Card>
  <Card title="Manage resources" icon="list" color="#FF6900" href="/cli/guides/resources">
    Datasets, monitors, dashboards, users, API keys and more share one
    `list | get | create | update | delete` pattern.
  </Card>
  <Card title="Script it" icon="terminal" color="#16A34A" href="/cli/guides/scripting">
    JSONL when piped, a JSON error envelope, `--jq`, `--dry-run`, and documented exit
    codes.
  </Card>
  <Card title="Run it in CI" icon="settings" color="#FF2056" href="/cli/guides/ci-cd">
    Read the key from the environment instead of a keychain, or use the container image,
    which has no shell.
  </Card>
</CardGroup>
